## TASK
Replace the mock-only path with a real `ApiSessionDriver` that talks to the agent
API (create/resume session, text turns, SSE UI pushes) through Next.js route handlers
(or same-origin proxy). Keep `MockSessionDriver` for `?state=` visual/e2e. Persist
session id + token so refresh and return visits resume (EC-08, EC-30, EC-31).

session cookie + SSE.

real or test-double API), harness/qa.mjs only if e2e tier needs a fixture flag.
Do not change services/agent except reading the API contract.

## REQUIREMENTS
- `SessionDriver` implementations: keep Mock; add ApiSessionDriver using
  `snapshot/sendText/startCall/endCall/onPush` from ARCH §6.
- Browser never holds the Anthropic/DB credentials. Prefer Next.js route handlers that
  forward to `PERSONA_AGENT_BASE_URL` with the session token server-side where needed;
  EventSource may use `?token=` per API README.
- Cookie or httpOnly storage for session id + token; refresh mid-flow restores transcript
  + checklist (EC-08). New visit with unfinished session resumes first missing slot (EC-30);
  graduated visit lands on home / welcome-back (EC-31).
- SSE: subscribe to `/v1/sessions/{id}/events`, apply `transcript`/`state`/
  `gmail_connect_card`/… pushes; de-dupe by event id; reconnect with Last-Event-ID.
- `startCall`/`endCall` may still be stubbed to the lease endpoints (answer null) —
  real WebRTC is FE-004/VOICE-001. UI call states should not regress mock `?state=` path.
- E2E: prefer spinning agent with FakeLlm + ephemeral Postgres (or a recorded stub
  server under apps/web/e2e) so `qa:e2e` needs no vendor network. Document how in OUTPUT.
- Env: `PERSONA_AGENT_BASE_URL` (and any proxy secret names) — never commit values.
