## Fixed and deployed tonight (agent 56ed4f5, LIVE 11:22pm PT; smoke 7/7; hosted browser call PASS)

   capped tokens) + **reaction-only phrasing** (model writes ≤ 1 short sentence; code appends
   the brain's chosen ask/offer/readback — it can't ask the wrong thing, re-introduce itself or
   skip the question). Privacy/injection answers are fixed policy text. Voice turns never
   make an extra LLM call on the text path.
2. Natural acknowledgements everywhere ("Nice to meet you, Darran.", "Juno. I like it.") — no "Got it: X".
3. Gmail "why" is given once per session; no "type your email in the chat" line on the call.
4. "I want to do more than Gmail" is a need, not a refusal (no instant graduation); added needs
   append ("automating emails and texting my mom").
5. Graduation line: "You're all set, Darran. Juno's first job: text my mom. You can connect Gmail
   from the main screen whenever you like." Post-call chat no longer says "Still left" after graduation.
6. Deploy hardening: the image ships `docs/product-facts.md` (first redeploy crashed on it; fixed
   in 2 min) and a text-LLM init failure degrades to templates instead of taking the API down.

## Voice hotfix + latency (Mon Sep 28, 12:52–1:50am PT, EM executor)
**Voice was broken 12:06am → ~1:00am PT.** GUARD-001 capped the voice LLM at `max_tokens=120`;
every `record_slots` call needs 149–168 tokens, so each tool call was truncated
(`stop_reason=max_tokens`) and every caller turn fell through to the silence floor ("Are you
still there?"). Hotfix 146cf19 (cap 512 + test that it is ≥ the extraction cap), deployed ~1:00am.

**Probe:** `apps/web/e2e/latency-probe.spec.ts` (real browser call to the hosted web + agent, a
`say`-generated caller WAV as the fake mic, WebAudio onset/offset on both tracks in the page
clock). Five caller turns per run, including a spelled name. Server side: one
`voice_turn_timing` log line per turn (LAT-001).

Server breakdown after (typical turn): turn wait 450 ms (VAD 0.2 s + Smart Turn + STT final) ·
LLM `record_slots` 1.0–1.1 s (compact args, ~100 tokens) · handler 150 ms (2 DB round trips
sjc→us-east-1) · Cartesia TTFB 110–200 ms. Browser adds ~450 ms (TURN relay + jitter buffer).
Earlier "connect ~6 s" readings included the name turn's LLM time (the Call button only appears
after it) and the probe's own click auto-wait; the real click→connected is ~2.1 s.

**Region:** not moved. After LAT-001 the DB costs 2 round trips (~145 ms). Moving the Fly agent to
iad would save ~130 ms per turn, but it puts ~60 ms each way onto the caller's audio path (West
Coast caller → TURN → iad), so the net gain is about zero. The LLM call is the main cost.

**Found by the live probe:** with VAD stop 0.2 s, Smart Turn ends a turn at each pause in a
spelled name. The brain saw only the last fragment and filled the name as "An". Fixed in be8e932
by joining the caller messages since the last handled turn; after the fix, all 3 runs filled "Darran".

**Known behaviour (not a regression):** after a name read-back, a caller who goes straight on
("I'd like help…") without saying yes gets the read-back again. Before the LAT changes the extractor
often tagged that as `affirm`. Whether to treat moving on as implicit confirmation is a product call.
